---
title: "Deploy with Docker Compose"
description: "Deploy Vibe Kanban Cloud on any server using Docker Compose"
---

Start a team board with its own PostgreSQL database, HTTPS, invite-only accounts, and a shared MCP endpoint. The steps use Docker Compose on a Linux server.

## Prerequisites

- A Linux server with Docker Engine, Docker Compose v2, Git, and OpenSSL.
- A hostname such as `kanban.example.com` pointing to the server in DNS.
- Inbound TCP ports 80 and 443 available for Caddy. Caddy obtains and renews the HTTPS certificate. The Compose file keeps PostgreSQL and ElectricSQL on its private network.

## Step 1: Prepare Your Server

On the server, install Docker Engine and the Compose plugin. [Docker Engine installation](https://docs.docker.com/engine/install/)

Clone the team deployment branch.

```bash
git clone --single-branch --branch self-hosted-password-invites \
  https://github.com/EmbeddedLLM/vibe-kanban.git vibe-kanban-prod
cd vibe-kanban-prod
```

## Step 2: Configure Authentication

### Invite-only password accounts

The default in this guide is `SELF_HOST_PASSWORD_ACCOUNTS=true`. On the first start with an empty database, the server creates an operator account using the email and password in `.env.remote`. The first operator's display name is **Admin**. Teammates choose their own display names and passwords when they accept an invite.

### Optional OAuth

To use OAuth on a fresh deployment, set `SELF_HOST_PASSWORD_ACCOUNTS=false`, omit the bootstrap email and password, and supply `GITHUB_OAUTH_CLIENT_ID` and `GITHUB_OAUTH_CLIENT_SECRET` or `GOOGLE_OAUTH_CLIENT_ID` and `GOOGLE_OAUTH_CLIENT_SECRET`. Use `https://kanban.example.com/v1/oauth/github/callback` or `https://kanban.example.com/v1/oauth/google/callback` as the provider callback, with your own hostname.

## Step 3: Create Environment File

Run this from the repository root. Replace the example hostname and admin email before running the command. The Compose project name determines the name of the new database volume. Use a unique name if you already have another board on this server.

```bash
(
  umask 077
  set -o noclobber
  cat > .env.remote <<EOF
COMPOSE_PROJECT_NAME=team-kanban
DOMAIN=kanban.example.com
DB_PASSWORD=$(openssl rand -hex 32)
ELECTRIC_ROLE_PASSWORD=$(openssl rand -hex 32)
VIBEKANBAN_REMOTE_JWT_SECRET=$(openssl rand -base64 48)
SELF_HOST_PASSWORD_ACCOUNTS=true
SELF_HOST_LOCAL_AUTH_EMAIL=admin@example.com
SELF_HOST_LOCAL_AUTH_PASSWORD=$(openssl rand -hex 24)
EOF
)
```

Save the generated admin password in your password manager. Keep `.env.remote` private and reuse it when updating this deployment.

## Step 4: Create Production Docker Compose

Create `docker-compose.prod.yml` in the `crates/remote` directory:

```yaml docker-compose.prod.yml
services:
  caddy:
    image: caddy:2-alpine
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    environment:
      DOMAIN: ${DOMAIN:?set DOMAIN in .env.remote}
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - remote-server

  remote-db:
    image: postgres:16-alpine
    command: ["postgres", "-c", "wal_level=logical"]
    restart: unless-stopped
    environment:
      POSTGRES_DB: remote
      POSTGRES_USER: remote
      POSTGRES_PASSWORD: ${DB_PASSWORD:?set DB_PASSWORD in .env.remote}
    volumes:
      - remote-db-data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U remote -d remote"]
      interval: 5s
      timeout: 5s
      retries: 5
      start_period: 5s

  electric:
    image: electricsql/electric:1.4.13
    working_dir: /app
    restart: unless-stopped
    environment:
      DATABASE_URL: postgresql://electric_sync:${ELECTRIC_ROLE_PASSWORD:?set ELECTRIC_ROLE_PASSWORD in .env.remote}@remote-db:5432/remote?sslmode=disable
      PG_PROXY_PORT: 65432
      LOGICAL_PUBLISHER_HOST: electric
      AUTH_MODE: insecure
      ELECTRIC_INSECURE: true
      ELECTRIC_MANUAL_TABLE_PUBLISHING: true
      ELECTRIC_USAGE_REPORTING: false
      ELECTRIC_FEATURE_FLAGS: allow_subqueries,tagged_subqueries
    volumes:
      - electric-data:/app/persistent
    depends_on:
      remote-db:
        condition: service_healthy
      remote-server:
        condition: service_healthy

  remote-server:
    build:
      context: ../..
      dockerfile: crates/remote/Dockerfile
      args:
        VITE_RELAY_API_BASE_URL: ${VITE_RELAY_API_BASE_URL:-}
        VITE_SELF_HOSTED_BOARD: "true"
    restart: unless-stopped
    depends_on:
      remote-db:
        condition: service_healthy
    environment:
      RUST_LOG: info,remote=info
      SERVER_DATABASE_URL: postgres://remote:${DB_PASSWORD:?set DB_PASSWORD in .env.remote}@remote-db:5432/remote
      SERVER_LISTEN_ADDR: 0.0.0.0:8081
      ELECTRIC_URL: http://electric:3000
      SERVER_PUBLIC_BASE_URL: https://${DOMAIN}
      GITHUB_OAUTH_CLIENT_ID: ${GITHUB_OAUTH_CLIENT_ID:-}
      GITHUB_OAUTH_CLIENT_SECRET: ${GITHUB_OAUTH_CLIENT_SECRET:-}
      GOOGLE_OAUTH_CLIENT_ID: ${GOOGLE_OAUTH_CLIENT_ID:-}
      GOOGLE_OAUTH_CLIENT_SECRET: ${GOOGLE_OAUTH_CLIENT_SECRET:-}
      VIBEKANBAN_REMOTE_JWT_SECRET: ${VIBEKANBAN_REMOTE_JWT_SECRET:?set VIBEKANBAN_REMOTE_JWT_SECRET in .env.remote}
      ELECTRIC_ROLE_PASSWORD: ${ELECTRIC_ROLE_PASSWORD}
      LOOPS_EMAIL_API_KEY: ${LOOPS_EMAIL_API_KEY:-}
      LOOPS_INVITE_TEMPLATE_ID: ${LOOPS_INVITE_TEMPLATE_ID:-cmhvy2wgs3s13z70i1pxakij9}
      LOOPS_REVIEW_READY_TEMPLATE_ID: ${LOOPS_REVIEW_READY_TEMPLATE_ID:-cmj47k5ge16990iylued9by17}
      LOOPS_REVIEW_FAILED_TEMPLATE_ID: ${LOOPS_REVIEW_FAILED_TEMPLATE_ID:-cmj49ougk1c8s0iznavijdqpo}
      SELF_HOST_PASSWORD_ACCOUNTS: ${SELF_HOST_PASSWORD_ACCOUNTS:-false}
      SELF_HOST_LOCAL_AUTH_EMAIL: ${SELF_HOST_LOCAL_AUTH_EMAIL:-}
      SELF_HOST_LOCAL_AUTH_PASSWORD: ${SELF_HOST_LOCAL_AUTH_PASSWORD:-}
      AZURE_STORAGE_ACCOUNT_NAME:
      AZURE_STORAGE_ACCOUNT_KEY:
      AZURE_STORAGE_CONTAINER_NAME:
      AZURE_STORAGE_ENDPOINT_URL:
      AZURE_STORAGE_PUBLIC_ENDPOINT_URL:
    healthcheck:
      test: ["CMD", "wget", "--spider", "-q", "http://127.0.0.1:8081/v1/health"]
      interval: 5s
      timeout: 5s
      retries: 10
      start_period: 10s

volumes:
  remote-db-data:
  electric-data:
  caddy_data:
  caddy_config:
```

## Step 5: Create Caddyfile

Create `crates/remote/Caddyfile` to serve the board and its MCP endpoint over HTTPS.

```text Caddyfile
{$DOMAIN} {
    reverse_proxy remote-server:8081
}
```

<Info>
The board and MCP endpoint share the domain in `.env.remote`. See [relay setup](#optional-enable-relaytunnel-in-production) to connect remote development machines through a relay.
</Info>

## Step 6: Deploy

```bash
cd crates/remote

docker compose --env-file ../../.env.remote -f docker-compose.prod.yml config --quiet
docker compose --env-file ../../.env.remote -f docker-compose.prod.yml up --build --wait
```

<Info>
Allow time for the first image build and for Caddy to obtain the certificate. Run the remaining Compose commands from `crates/remote` using the same environment file and project name.
</Info>

## Step 7: Verify Deployment

Check the health endpoint with your own hostname. A healthy server returns `"status": "ok"`.

```bash
curl -fsS https://kanban.example.com/v1/health
```

1. Open the board at the same HTTPS hostname. In password mode, sign in with the admin email and password from `.env.remote`.
2. Open **Settings → Organizations**, create a team organisation, and enter the name you want. Use this team organisation for invitations.
3. Select the team organisation under **Settings → Projects**. Select **Initial Project**, enter your preferred project name, and save.

Once you confirm the operator can sign in, remove `SELF_HOST_LOCAL_AUTH_EMAIL` and `SELF_HOST_LOCAL_AUTH_PASSWORD` from `.env.remote`. Recreate the server container to remove the bootstrap credentials from its environment.

```bash
docker compose --env-file ../../.env.remote -f docker-compose.prod.yml up -d --no-deps --wait remote-server
```

Sign in again using the password you saved to confirm the operator account works after the restart.

### Invite teammates with password accounts

1. In the team organisation, open **Settings → Organizations → Members** and select **Invite member**.
2. Enter an email for a new account, choose their role, and select **Create invitation**. Copy the link and share it privately. Password-account invitations are delivered manually.
3. Your teammate opens the link, checks the email and organisation, and chooses a display name and password. They can then sign in with that email and password.
4. Under **Pending invitations**, you can copy a valid link again, revoke it, or replace it. Links expire after seven days and can be used once.

### Connect team agents

Each member can create a project-scoped key under **Settings → MCP Access** and choose when it expires. The default is 30 days. A key set to **Never** stays active until it is revoked or the member loses project access. Follow the [MCP setup guide](/integrations/vibe-kanban-mcp-server#connect-to-a-self-hosted-board) for Codex, Claude Code, and Pi. Other clients can use `https://kanban.example.com/mcp` on your domain with Streamable HTTP and the bearer key. Ask the agent to list the columns on the board to check its connection. Kanban changes are attributed to the key’s owner.

### Recover a password account

Members can change a known password from the account menu. If they lose it, the server operator can issue a reset link using Docker access:

```bash
docker compose --env-file ../../.env.remote -f docker-compose.prod.yml \
  exec -T remote-server /usr/local/bin/remote local-reset-link teammate@example.com
```

Share the link privately. It expires in 30 minutes. Redeeming it signs the member out on all devices and revokes their MCP keys. A routine password change signs the member out and preserves their MCP keys.

## Optional: Enable Relay/Tunnel in Production

Relay/tunnel support requires:

1. A running `relay-server` service
2. Reverse proxy routing for both `relay.your-domain.com` and `*.relay.your-domain.com`
3. A wildcard certificate for `*.relay.your-domain.com` (or equivalent managed TLS at your edge)
4. `VITE_RELAY_API_BASE_URL` set to your public relay API base URL before building `remote-server`

### Add relay-server to docker compose

```yaml docker-compose.prod.yml
  relay-server:
    build:
      context: ../..
      dockerfile: crates/relay-tunnel/Dockerfile
    restart: unless-stopped
    depends_on:
      remote-db:
        condition: service_healthy
    environment:
      RUST_LOG: info
      SERVER_DATABASE_URL: postgres://remote:${DB_PASSWORD:?set DB_PASSWORD in .env.remote}@remote-db:5432/remote
      RELAY_LISTEN_ADDR: 0.0.0.0:8082
      VIBEKANBAN_REMOTE_JWT_SECRET: ${VIBEKANBAN_REMOTE_JWT_SECRET}
```

### Add relay proxy routes

Your reverse proxy must route:

- `relay.your-domain.com` -> `relay-server:8082`
- `*.relay.your-domain.com` -> `relay-server:8082`

<Warning>
Standard ACME HTTP challenge does not issue wildcard certificates. For wildcard relay hostnames, use a DNS-based ACME challenge or another edge provider that can terminate wildcard TLS certificates.
</Warning>

## Updating

Back up the database before updating. Keep the Compose project name, database volume, and JWT secret across upgrades. From `crates/remote`, update the checked-out deployment branch and start the new build.

```bash
git pull --ff-only
docker compose --env-file ../../.env.remote -f docker-compose.prod.yml up --build --wait
```

## Backup and Restore

### Backup Database

```bash
umask 077
docker compose --env-file ../../.env.remote -f docker-compose.prod.yml exec -T remote-db \
  pg_dump -U remote remote > backup_$(date +%Y%m%d).sql
```

### Restore Database

Restore the backup into an empty database before starting the board.

```bash
docker compose --env-file ../../.env.remote -f docker-compose.prod.yml exec -T remote-db \
  psql -U remote remote < backup_20240101.sql
```

## Monitoring

### View Logs

```bash
# All services
docker compose --env-file ../../.env.remote -f docker-compose.prod.yml logs -f

# Specific service
docker compose --env-file ../../.env.remote -f docker-compose.prod.yml logs -f remote-server
```

### Check Service Health

```bash
docker compose --env-file ../../.env.remote -f docker-compose.prod.yml ps
```

## Troubleshooting

<AccordionGroup>
<Accordion title="Settings are slow over plain HTTP">
Browsers can queue API requests behind live board sync requests on HTTP/1.1. The self-hosted board uses shorter live sync requests on plain HTTP. Use the HTTPS Caddy endpoint for production so the browser can multiplex requests over HTTP/2.
</Accordion>

<Accordion title="SSL certificate issues">
Caddy obtains the HTTPS certificate automatically. Check that:
- Your domain's DNS is correctly pointing to your server
- Ports 80 and 443 are open in your firewall
- Your domain is correctly set in the environment
</Accordion>

<Accordion title="Database connection refused">
The server may start before the database is ready. Check:

```bash
docker compose --env-file ../../.env.remote -f docker-compose.prod.yml logs remote-db
docker compose --env-file ../../.env.remote -f docker-compose.prod.yml restart remote-server
```
</Accordion>

<Accordion title="ElectricSQL fails to connect">
ElectricSQL requires the `electric_sync` database user, which the Remote Server creates automatically on first startup. If ElectricSQL cannot connect:

1. Check that the Remote Server started successfully and ran its migrations
2. Verify `ELECTRIC_ROLE_PASSWORD` matches in both your `.env.remote` and the Electric service config
3. Restart ElectricSQL after the Remote Server is healthy:

```bash
docker compose --env-file ../../.env.remote -f docker-compose.prod.yml restart electric
```
</Accordion>

<Accordion title="Out of memory errors">
If the build fails with memory errors, you may need a server with more RAM or add swap:

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
```
</Accordion>
</AccordionGroup>
